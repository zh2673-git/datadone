## 二、数据规矩（Pydantic 模型）

```python
# src/ai/models.py
from typing import Optional, List
from pydantic import BaseModel, Field


class EvidenceRef(BaseModel):
    """证据引用：每条 AI 结论必须能回溯到规则信号"""
    证据类型: str  # anomaly / pattern / timeline / risk / key_transaction
    证据ID: str
    说明: str = ""


class NarrativeBlock(BaseModel):
    """叙事块"""
    标题: str
    内容: str
    级别: str  # case / person / clue
    本方姓名: Optional[str] = None
    证据引用: List[EvidenceRef] = Field(default_factory=list)
    置信度: str = "中"  # 高 / 中 / 低


class Hypothesis(BaseModel):
    """调查假设"""
    假设ID: str
    标题: str
    描述: str
    验证方向: List[str]
    证据引用: List[EvidenceRef] = Field(default_factory=list)
    风险等级: str = "中"  # 高 / 中 / 低


class QAPair(BaseModel):
    """问答结果"""
    问题: str
    回答: str
    证据引用: List[EvidenceRef] = Field(default_factory=list)
    是否可回答: bool = True
    未回答原因: str = ""


class AIInsight(BaseModel):
    """单个人员的 AI 分析产物"""
    本方姓名: str
    案件级叙事: List[NarrativeBlock] = Field(default_factory=list)
    人员级叙事: List[NarrativeBlock] = Field(default_factory=list)
    线索级叙事: List[NarrativeBlock] = Field(default_factory=list)
    调查假设: List[Hypothesis] = Field(default_factory=list)
    问答历史: List[QAPair] = Field(default_factory=list)


class ValidationResult(BaseModel):
    """符号校验结果"""
    通过: bool
    错误列表: List[str] = Field(default_factory=list)
    警告列表: List[str] = Field(default_factory=list)


class GenerationResult(BaseModel):
    """LLM 生成结果通用封装"""
    成功: bool
    原始输出: str = ""
    结构化输出: Optional[dict] = None
    错误信息: str = ""
```

## 三、模块接口契约

### 3.1 LLM 接入层（`src/ai/provider.py`）

**类**：`LLMProvider`

**属性**：

| 属性 | 类型 | 说明 |
|---|---|---|
| `provider_type` | str | openai / ollama / mock |
| `model_name` | str | 当前使用的模型 |
| `api_base` | Optional[str] | 本地或远端地址 |
| `api_key` | Optional[str] | API Key |
| `timeout` | float | 请求超时 |

**方法**：

| 方法 | 签名 | 说明 |
|---|---|---|
| `generate` | `(prompt: str, schema: dict, temperature: float = 0.3) -> GenerationResult` | 调用 LLM 并返回结构化结果 |
| `health_check` | `() -> bool` | 检查 Provider 是否可用 |
| `estimate_tokens` | `(prompt: str) -> int` | 估算输入 Token 数 |

**路由**：根据 `provider_type` 路由到不同后端实现。

### 3.2 Prompt 管理层（`src/ai/prompt_manager.py`）

**类**：`PromptManager`

**属性**：

| 属性 | 类型 | 说明 |
|---|---|---|
| `template_dir` | str | Prompt 模板目录 |
| `version` | str | 当前模板版本 |
| `templates` | dict | 已加载的 Jinja2 模板 |

**方法**：

| 方法 | 签名 | 说明 |
|---|---|---|
| `load` | `(name: str) -> Template` | 加载模板 |
| `render` | `(name: str, context: dict) -> str` | 渲染 Prompt |
| `list_templates` | `() -> list[str]` | 列出可用模板 |

**模板清单**：

- `narrative_case.j2`：案件级叙事
- `narrative_person.j2`：人员级叙事
- `narrative_clue.j2`：线索级叙事
- `hypothesis.j2`：调查假设
- `qa.j2`：问答
- `validate.j2`：输出校验辅助

### 3.3 符号校验层（`src/ai/symbolic_validator.py`）

**类**：`SymbolicValidator`

**属性**：

| 属性 | 类型 | 说明 |
|---|---|---|
| `input_schema` | dict | 允许输入的字段白名单 |
| `output_schema` | dict | 强制输出的 JSON Schema |
| `evidence_rules` | list | 证据引用校验规则 |

**方法**：

| 方法 | 签名 | 说明 |
|---|---|---|
| `validate_input` | `(analysis_result: AnalysisResult) -> ValidationResult` | 校验输入是否合规 |
| `validate_output` | `(raw_output: str, schema: dict) -> GenerationResult` | 校验并解析输出 |
| `check_hallucination` | `(ai_insight: AIInsight, source: AnalysisResult) -> ValidationResult` | 幻觉检测 |
| `check_consistency` | `(ai_insight: AIInsight, source: AnalysisResult) -> ValidationResult` | 一致性检测 |

**关键规则**：

1. `evidence_refs` 不能为空。
2. `evidence_refs.证据ID` 必须在 `AnalysisResult` 中存在对应条目。
3. AI 描述中的金额、人数、次数等数字必须与源信号一致（允许四舍五入）。
4. 不允许出现规则引擎未发现的对手姓名。

### 3.4 AI 分析引擎（`src/ai/narrative_engine.py` 等）

**类**：`NarrativeEngine` / `HypothesisEngine` / `QAEngine`

**公共依赖**：`LLMProvider`, `PromptManager`, `SymbolicValidator`

#### NarrativeEngine

| 方法 | 签名 | 说明 |
|---|---|---|
| `generate_case_narrative` | `(result: AnalysisResult) -> list[NarrativeBlock]` | 案件级叙事（跨人员） |
| `generate_person_narrative` | `(result: AnalysisResult, person: str) -> list[NarrativeBlock]` | 单人员叙事 |
| `generate_clue_narratives` | `(result: AnalysisResult, person: str) -> list[NarrativeBlock]` | 逐条线索叙事 |

#### HypothesisEngine

| 方法 | 签名 | 说明 |
|---|---|---|
| `generate_hypotheses` | `(result: AnalysisResult, person: str) -> list[Hypothesis]` | 生成调查假设 |
| `rank_hypotheses` | `(hypotheses: list[Hypothesis]) -> list[Hypothesis]` | 按证据强度排序 |

#### QAEngine

| 方法 | 签名 | 说明 |
|---|---|---|
| `answer` | `(result: AnalysisResult, question: str, person: Optional[str]) -> QAPair` | 回答问题 |
| `is_answerable` | `(question: str) -> bool` | 判断问题是否在系统能力范围内 |

### 3.5 AI 报告生成器（`src/ai/ai_report_builder.py`）

**类**：`AIReportBuilder`

**属性**：

| 属性 | 类型 | 说明 |
|---|---|---|
| `narrative_engine` | NarrativeEngine | 叙事生成器引用 |
| `hypothesis_engine` | HypothesisEngine | 假设生成器引用 |

**方法**：

| 方法 | 签名 | 说明 |
|---|---|---|
| `enrich` | `(report_data: ReportData, insights: dict[str, AIInsight]) -> ReportData` | 把 AI 产物注入报告数据 |
| `build_ai_summary_sheet` | `(insights: dict[str, AIInsight]) -> list[dict]` | 生成 Excel AI 摘要工作表 |
| `build_ai_word_sections` | `(insights: dict[str, AIInsight]) -> dict[str, list[dict]]` | 生成 Word AI 章节 |

### 3.6 失败降级层（`src/ai/fallback_manager.py`）

**类**：`FallbackManager`

**属性**：

| 属性 | 类型 | 说明 |
|---|---|---|
| `enabled` | bool | 是否启用降级 |
| `fallback_reason` | Optional[str] | 降级原因 |

**方法**：

| 方法 | 签名 | 说明 |
|---|---|---|
| `should_fallback` | `(error: Exception) -> bool` | 判断是否触发降级 |
| `create_empty_insight` | `(person: str) -> AIInsight` | 生成空 AI 产物 |
| `log_fallback` | `(reason: str) -> None` | 记录降级日志 |

## 四、AI 开关与默认行为

### 4.1 可选开关设计

AI 分析被设计为**可插拔的增强层**，不是核心分析路径的必需部分。系统通过三层开关控制：

| 开关层级 | 控制点 | 说明 |
|---|---|---|
| **全局默认** | `config/config.json` 中的 `ai.enabled` | 默认 `false`，首次使用不会触发 AI |
| **运行时参数** | `Application(ai_enabled=True)` | 代码层面显式启用 |
| **CLI 菜单** | 运行分析时提示「是否启用 AI 解读」 | 用户每次可选择 |

**设计原则**：

- **默认关闭**：不安装 LLM、不配 API Key，系统仍能完整运行并输出原有报告。
- **显式开启**：用户必须主动选择「启用 AI 分析」，AI 层才会被调用。
- **失败透明**：AI 层失败时只影响 AI 内容，不影响规则报告生成，并在日志中记录原因。

### 4.2 开关行为矩阵

| AI 开关 | LLM 可用 | 输出结果 |
|---|---|---|
| 关闭 | 无需关心 | 原有 Excel + Word 规则报告 |
| 开启 | 可用 | 规则报告 + AI 叙事 / 假设 / 问答能力 |
| 开启 | 不可用 | 规则报告 + 日志提示「AI 已跳过」 |
| 开启 | 部分失败 | 规则报告 + 成功模块的 AI 内容 |

### 4.3 对现有代码的侵入性

- 现有 `AnalysisEngine` 不做任何修改。
- 现有 `ReportBuilder` 增加 `enrich_with_ai()` 方法，但仅在 `ai_enabled=True` 且存在 `ai_insights` 时调用。
- 现有 `ExcelExporter` / `WordExporter` 增加对 AI 章节的渲染，无 AI 内容时行为不变。

## 五、AI 分析完整流程

### 5.1 正常流程（AI 开启且 LLM 可用）

```
用户选择「启用 AI 分析」
        │
        ▼
┌───────────────────┐
│   1. 数据加载     │  ← 银行 / 微信 / 支付宝 / 话单 Loader
│   （现有流程）    │
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│   2. 规则分析     │  ← 11 步分析引擎
│   （现有流程）    │
└─────────┬─────────┘
          │
          ▼  AnalysisResult
┌───────────────────┐
│   3. 输入校验     │  ← SymbolicValidator.validate_input()

          │
          ▼
┌───────────────────┐
│   7. 输出校验     │  ← SymbolicValidator.validate_output()
│                   │     校验 JSON Schema 是否合法

┌───────────────────┐

### 5.3 交互式问答流程

```
用户输入自然语言问题
        │
        ▼
┌───────────────────┐
│ 1. 判断是否可回答 │  ← QAEngine.is_answerable()
│                   │     例如：拒绝法律定性类问题
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 2. 提取相关信号   │  ← 从 AnalysisResult 中检索与问题相关的
│                   │     异常、模式、时序链、风险等
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 3. 组装问答 Prompt│  ← PromptManager.render('qa.j2', ...)
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 4. LLM 生成回答   │  ← LLMProvider.generate()
└─────────┬─────────┘
          │
          ▼
┌───────────────────┐
│ 5. 符号校验       │  ← 必须有 evidence_refs
└─────────┬─────────┘

          ▼

### 5.4 关键边界说明

- **AI 不触碰原始流水**：LLM 的输入只来自 `AnalysisResult`，不来自 `bank_df` / `wechat_df` 等原始 DataFrame。
- **每步都有校验**：生成前校验输入、生成后校验输出、再校验事实溯源和一致性。
- **失败只影响 AI 内容**：任何一步失败都不会中断规则分析或报告导出。
- **所有结论可回溯**：每个 `NarrativeBlock`、`Hypothesis`、`QAPair` 都携带 `evidence_refs`。

## 六、全局状态与数据流转

### 6.1 AI 层在 Application 中的位置

```python
# src/application.py 新增
from src.ai.provider import LLMProvider
from src.ai.narrative_engine import NarrativeEngine
from src.ai.hypothesis_engine import HypothesisEngine
from src.ai.ai_report_builder import AIReportBuilder
from src.ai.fallback_manager import FallbackManager

class Application:
    def __init__(self, ai_enabled: bool = False):
        # ... 现有初始化 ...
        self.ai_enabled = ai_enabled
        if ai_enabled:
            self.llm_provider = LLMProvider.from_config()
            self.narrative_engine = NarrativeEngine(self.llm_provider, ...)
            self.hypothesis_engine = HypothesisEngine(self.llm_provider, ...)
            self.ai_report_builder = AIReportBuilder(self.narrative_engine, self.hypothesis_engine)
            self.fallback_manager = FallbackManager()
```

### 6.2 AI 分析调用点

```python
def analyze(self, analysis_type: str = 'all', ai_enabled: bool = False) -> AnalysisResult:
    result = self.analysis_engine.analyze(self._state, analysis_type)
    if ai_enabled and self.ai_enabled:
        try:
            result.ai_insights = self._generate_ai_insights(result)
        except Exception as e:
            self.fallback_manager.log_fallback(str(e))
            result.ai_insights = {}
    self._state['analysis_result'] = result
    return result
```

## 七、失败模式编码

### 7.1 思考层失败

| 失败场景 | 处理动作 |
|---|---|
| 本质定义无法解释 AI 问答能力 | 回到方案文档重新审视，确认 AI 不生成新信号 |
| AI 模块接口无法对齐 | 回到架构设计，统一输入/输出 Schema |
| Prompt 模板与代码版本不匹配 | 增加版本校验，启动时检查 |

### 7.2 产物层失败

| 失败场景 | 处理动作 |
|---|---|
| LLM Provider 不可达 | 触发降级，返回空 AI 产物，继续规则报告 |
| AI 输出无法解析为 JSON | 重试 1 次；仍失败则丢弃该条，记录日志 |
| AI 输出缺少 evidence_refs | 符号校验失败，不进入正式报告 |
| AI 输出与规则信号矛盾 | 以规则信号为准，AI 结论标记为「待复核」 |
| 单个人员 AI 生成失败 | 仅该人员无 AI 内容，其他人员正常生成 |
| Token 超限 | 对长输入做信号摘要压缩后再调用 |
| 本地模型未安装 | 提示用户安装或切换 Provider |

## 八、类-属性-方法-路由汇总

由本质定义「信号 → 叙事」锚定：

| 维度 | 内容 | 回溯说明 |
|---|---|---|
| **类** | `AISystem` / `AIInsight` | 信号翻译系统 / 翻译产物 |
| **属性** | `llm_provider`, `symbolic_validator`, `narrative_engine`, `hypothesis_engine`, `qa_engine`, `report_builder`, `fallback_manager` | 分别对应语言能力、审计约束、叙事、假设、交互、交付、安全边界 |
| **方法** | `generate_narrative`, `generate_hypotheses`, `answer`, `enrich_report`, `validate`, `fallback` | 对应「信号 → 叙事/假设/回答/报告」以及校验与降级 |
| **路由** | 单人 / 合并 / 问答 / 离线 | 对应不同调查场景下叙事能力的情境化适配 |
