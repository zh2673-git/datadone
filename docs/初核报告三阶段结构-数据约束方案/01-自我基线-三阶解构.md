# 01-自我基线 - 三阶解构

> 分析日期：2026-05-04 | 场景：通用知识探索（场景A）

## 一、是什么（坡度三阶段）

### 阶段1：点出概念

> **一句话定义**：自我基线是"个人行为正常值的标尺"——用被核查人自身的历史数据统计出"正常情况下收支多少、跟谁交易、什么时候交易"，作为判断异常的参照系。

**本质特征**：

| 推导要素 | 逻辑分析 | 结论 |
|---------|---------|------|
| **参照来源** | 无外部数据，参照从何而来？ | 只能从自身历史数据推导 |
| **核心功能** | 基线存在的唯一目的是什么？ | 为"异常判定"提供对比基准——没有基线就没有异常 |
| **统计本质** | 基线在统计上是什么？ | 行为指标的概率分布（均值+离散度），落在95%区间外即为异常 |
| **动态性** | 人的行为会随时间变化 | 基线不是固定值，而是有趋势的变化区间 |

### 阶段2：建立联系

| 属性名 | 类型 | 说明 | 深入？ |
|-------|-----|-----|-------|
| **资金基线** | 子模块 | 月均收支金额/频次/对手数的分布 | ✅ 需深入 → [[01-01-资金基线-三阶解构]] |
| **时间基线** | 子模块 | 交易时间分布/通话时间分布 | ✅ 需深入 → [[01-02-时间基线-三阶解构]] |
| **对手基线** | 子模块 | 核心对手/对手稳定性/新增对手频率 | ✅ 需深入 → [[01-03-对手基线-三阶解构]] |
| **现金基线** | 属性 | 存取现比例/频率/金额分布 | ❌ 当前文档说明 |
| **趋势方向** | 属性 | 基线是上升/下降/平稳 | ❌ 当前文档说明 |

### 阶段3：详细解释

**现金基线**
- **定义**：被核查人使用现金的习惯量化
- **关键点**：
  - 存取现金额占总收支的比例 → 刻画现金依赖度
  - 存取现频率（月均次数） → 刻画现金行为节奏
  - 存取现金额分布（均值/中位数/最大值） → 刻画现金行为规模
  - **初核意义**：如果某人平时很少取现，突然集中取现大额 → 偏离现金基线

**趋势方向**
- **定义**：基线指标随时间的变化方向
- **关键点**：
  - 用线性回归或移动平均判断趋势方向（↑上升/→平稳/↓下降）
  - 趋势本身也是信息：月收入持续上升 → 可能意味着新收入来源出现
  - **报告呈现**：基线表格增加"近期趋势"列

## 二、为什么（坡度三阶段）

### 阶段1：点出概念

> **一句话总结**：自我基线是整个分析逻辑链的起点——没有基线，"异常"就无从定义，后续所有异常识别、模式归类、风险研判都将失去逻辑支撑。

### 阶段2：建立联系

| 因果 | 因 | 果 | 逻辑 | 类比 |
|-----|---|---|-----|------|
| **无基线则无异常** | 不知道"正常"是多少 | 无法判断什么算"异常" | 没有尺子就无法量长度 | 不知道正常血压就无法诊断高血压 |
| **基线质量决定异常质量** | 基线计算不准确 | 误判：把正常当异常或把异常当正常 | 尺子刻度不准则测量失真 | 血压计校准偏差→误诊 |
| **基线是动态的** | 人的行为随时间演变 | 静态基线会失效 | 标尺需要定期校准 | 血压正常值随年龄调整 |
| **基线是相对的** | 没有外部群体参照 | 只能做"相对异常"判断 | 内部参照的局限 | 只知道自己的体温变化，不知道37.5是否算发烧 |

### 阶段3：详细解释

**理论依据**：
- 统计学原理：正态分布下，约95%的观测值落在均值±2个标准差范围内，超出即为小概率事件
- 行为分析原理：人的日常行为具有惯性（习惯性），短期内大幅偏离习惯即需关注
- 纪委监委实务：初核中"对比本人日常行为"是标准做法，自我基线正是这一做法的量化实现

**质疑验证**：
- **质疑**：数据时间跨度不够长，基线可靠吗？
- **验证**：
  - 数据跨度≥6个月 → 基线较可靠（至少覆盖半年周期）
  - 数据跨度3-6个月 → 基线可用但需标注"基线数据有限"
  - 数据跨度<3个月 → 基线不可靠，报告中需明确标注"数据不足以建立稳定基线"
  - **实现**：基线输出增加"数据充足度"字段

## 三、怎么做（坡度三阶段）

### 阶段1：点出概念

> **一句话概述**：按月度粒度统计个人行为指标的均值和标准差，输出为结构化的基线参照表。

### 阶段2：建立联系

| 步骤 | 动作 | 产出 | 注意事项 |
|-----|------|------|---------|
| **1.数据准备** | 合并三平台账单为统一交易流水 | 合并后的DataFrame | 统一日期格式、金额取绝对值、标注平台来源 |
| **2.按月聚合** | 按年月分组计算各项指标 | 月度指标表 | 处理缺失月份（插值或标注） |
| **3.统计基线** | 对月度指标计算均值/标准差/分位数 | 基线对象(PersonBaseline) | 数据量不足时标注"基线有限" |
| **4.趋势计算** | 对月度指标做线性回归 | 趋势方向(↑→↓) | 至少需要4个月数据才计算趋势 |
| **5.输出** | 基线对象传入下游分析 | PersonBaseline | 基线是只读的，下游不可修改 |

### 阶段3：详细解释

**数据模型设计**：

```python
@dataclass
class PersonBaseline:
    """个人行为基线"""
    本方姓名: str
    数据充足度: str  # "充足"(≥6月) / "有限"(3-6月) / "不足"(<3月)
    数据月数: int
    
    # 资金基线
    月均收入: float
    月均收入_std: float  # 标准差
    月均支出: float
    月均支出_std: float
    月均交易次数: float
    月均交易次数_std: float
    月均交易对手数: float
    月均交易对手数_std: float
    
    # 金额分布
    单笔金额均值: float
    单笔金额中位数: float
    单笔金额_P25: float  # 25分位数
    单笔金额_P75: float  # 75分位数
    
    # 时间基线
    工作时间交易占比: float  # 9-17点
    深夜交易占比: float     # 22-6点
    周末交易占比: float
    
    # 现金基线
    存取现月均金额: float
    存取现占收支比: float
    
    # 通话基线
    月均通话次数: float
    月均通话时长分钟: float
    月均通话对手数: float
    
    # 趋势
    收入趋势: str   # "上升"/"下降"/"平稳"
    支出趋势: str
    对手数趋势: str
    
    # 月度明细（用于异常对比）
    月度明细: list[MonthlyMetric]  # 保留每月原始值
```

**四层设计**：

| 层面 | 设计内容 |
|-----|---------|
| **数据规矩** | `PersonBaseline` Dataclass，字段类型/约束/默认值已定义；`MonthlyMetric` 子结构 |
| **数据存储** | 内存中 `dict[str, PersonBaseline]`，按本方姓名索引；基线在分析完成后只读 |
| **数据流转** | 合并DataFrame → 按月聚合 → 统计均值/标准差 → 计算趋势 → 输出PersonBaseline |
| **接口层** | `BaselineAnalyzer.analyze(all_data, call_data) -> dict[str, PersonBaseline]` |

**异常判定的接口设计**：

```python
def is_anomaly(value: float, baseline_mean: float, baseline_std: float, 
               threshold_sigma: float = 2.0) -> tuple[bool, float]:
    """
    判断某值是否偏离基线异常
    Returns: (是否异常, 偏离倍数)
    """
    if baseline_std == 0:
        return (value != baseline_mean, float('inf') if value != baseline_mean else 0)
    sigma = abs(value - baseline_mean) / baseline_std
    return (sigma > threshold_sigma, round(sigma, 2))
```

**验证方法**：
- 检查点1：基线月均收入 ≈ (总收入 / 数据月数) ± 合理误差
- 检查点2：标准差 > 0（除非所有月份收支完全相同）
- 检查点3：数据充足度标注与实际月数一致
