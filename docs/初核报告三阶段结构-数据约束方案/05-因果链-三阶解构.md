## 一、是什么（坡度三阶段）

### 阶段1：点出概念

> **一句话定义**：因果链是"证据的骨架"——将通话和资金事件按时间排列，构建"A→B→C"的时序关联链，证明事件之间存在时间上的因果可能性。

**本质特征**：

| 推导要素 | 逻辑分析 | 结论 |
|---------|---------|------|
| **核心价值** | 因果链解决了什么问题？ | 从"同时发生"升级为"先后发生"——证明因果方向 |
| **构建基础** | 因果链需要什么数据？ | 时间戳精确的事件序列（通话时间+交易时间） |
| **判定逻辑** | 什么构成因果链？ | 通话→N小时内→资金（或反向），且重复出现≥2次 |
| **局限** | 因果链能证明什么/不能证明什么？ | 能证明时间上的先后关联，不能证明法律上的因果关系 |

### 阶段2：建立联系

四类数据约束下可构建的5种证据链：

| 链类型 | 数据来源 | 核心逻辑 | 深入？ |
|-------|---------|---------|-------|
| **通讯-资金时序链** | 话单+账单 | 通话→N小时→资金→N小时→通话 | ✅ 需深入 → [[05-01-通讯资金时序链-三阶解构]] |
| **多源交叉验证链** | 三类账单+话单 | 同一对手在≥2个平台同时出现 | ✅ 需深入 → [[05-02-多源交叉验证链-三阶解构]] |
| **间接资金链** | 账单 | A→B→C的大额资金递归追踪 | ❌ 当前项目已有 |
| **存取现关联链** | 银行+话单 | 存取现当天/±3天有通话 | ❌ 当前项目已有(需扩展) |
| **金额对应链** | 账单 | A→B的金额≈B→C的金额 | ❌ 当前文档说明 |

### 阶段3：详细解释

**金额对应链**
- **定义**：不同人员之间资金流转金额的高度对应关系
- **关键点**：
  - A转给B 50万，B转给C 48万（差额2万可能是手续费/扣点）
  - 金额对应率 = min(流出, 流入) / max(流出, 流入) > 0.9 则视为对应
  - **意义**：证明资金是"过桥"而非"真实交易"
  - **当前项目缺失**：大额追踪只追踪了"A→B→C"的层级关系，没有检查金额对应关系

**存取现关联链的扩展**
- **当前项目**：只匹配当天
- **扩展到±3天**：取现后3天内给某人转账 → 资金去向线索
- **增加方向**：某人转账给被核查人→被核查人存现 → 资金来源线索

## 二、为什么（坡度三阶段）

### 阶段1：点出概念

> **一句话总结**：因果链是"从相关性到因果性的桥梁"——单独的通话记录和资金记录只能说明"存在"，时序链能说明"先后"，从而暗示因果方向。

### 阶段2：建立联系

| 因果 | 因 | 果 | 逻辑 | 类比 |
|-----|---|---|-----|------|
| **有时序才有方向** | 知道A和B同时存在 | 不知道谁因谁果 | 先因后果 | 先下雨后地湿→雨是因 |
| **有重复才有说服力** | 单次通话后资金可能是巧合 | 重复3次以上→非偶然 | 大数定律 | 1次巧合，3次规律 |
| **有多源才有验证** | 单一数据源的链可能是巧合 | 多源交叉验证的链更可信 | 互证原理 | 两个独立证人的证词比一个可信 |
| **有金额对应才有路径** | 只知道A给了B | 不知道B是否转给了C | 资金追踪 | 知道钱从哪来到哪去 |

### 阶段3：详细解释

**"通话→资金→通话"三段链的特殊意义**：

这是初核中最有价值的证据链模式，因为它暗示了：
1. **通话（联络）**：双方商议
2. **资金（执行）**：资金转移
3. **通话（确认）**：确认到账/完成

三段链比两段链（通话→资金）的证据强度高得多，因为它排除了"通话后恰好有资金"的巧合解释。

**时序链的证据强度分级**：

| 链模式 | 证据强度 | 说明 |
|-------|---------|------|
| 通话→资金（2段） | 弱 | 可能是巧合 |
| 通话→资金→通话（3段） | 中 | 排除了部分巧合解释 |
| 3段链重复≥3次 | 强 | 统计上非偶然 |
| 3段链+多源交叉验证 | 很强 | 两个独立证据体系一致 |

## 三、怎么做（坡度三阶段）

### 阶段1：点出概念

> **一句话概述**：将同一对手的通话和资金事件按时间排列，检测"通话→N小时内→资金"的时序模式，构建时序事件链。

### 阶段2：建立联系

| 步骤 | 动作 | 产出 | 注意事项 |
|-----|------|------|---------|
| **1.时间对齐** | 将通话和交易时间统一为datetime | 统一时间轴 | 处理跨日、时区问题 |
| **2.按对手分组** | 将同一对(本方,对方)的所有事件合并 | 对手事件组 | 通话和资金都要包含 |
| **3.时序排列** | 按时间排序所有事件 | 时间序列 | 标注事件类型(通话/资金)和方向 |
| **4.模式检测** | 滑动窗口检测"通话→N小时→资金" | 时序链 | 窗口大小可配置(默认24h) |
| **5.链强度评估** | 计算链的重复次数和交叉验证数 | 链强度 | 重复越多越强 |

### 阶段3：详细解释

**时序链数据模型**：

```python
@dataclass
class TimelineEvent:
    """时序链中的单个事件"""
    时间: datetime
    事件类型: str      # "通话" / "资金"
    方向: str          # "主叫"/"被叫" / "收入"/"支出"
    金额: float        # 通话为时长(秒)，资金为金额
    对手: str
    平台: str          # "银行"/"微信"/"支付宝"/"话单"
    备注: str

@dataclass
class TimelineChain:
    """一条时序链"""
    本方姓名: str
    对方姓名: str
    事件序列: list[TimelineEvent]
    链模式: str        # "通话→资金"/"通话→资金→通话"
    链强度: str        # 弱/中/强/很强
    重复次数: int      # 该对手的同类链出现次数
    时间窗口: int      # 检测窗口(小时)
    关键证据描述: str
```

**时序链检测算法**：

```python
def detect_timeline_chains(
    person: str, 
    opponent: str,
    bill_data: pd.DataFrame, 
    call_data: pd.DataFrame,
    window_hours: int = 24,
    min_repeats: int = 2
) -> list[TimelineChain]:
    """
    检测通讯-资金时序链
    """
    # 1. 合并通话和资金事件
    events = []
    for _, row in call_data.iterrows():
        if row['本方姓名'] == person and row['对方姓名'] == opponent:
            events.append(TimelineEvent(
                时间=row['通话时间'], 事件类型='通话',
                方向=row['呼叫类型'], 金额=row.get('通话时长', 0),
                对手=opponent, 平台='话单', 备注=''
            ))
    for _, row in bill_data.iterrows():
        if row['本方姓名'] == person and row['对方姓名'] == opponent:
            events.append(TimelineEvent(
                时间=row['交易日期'], 事件类型='资金',
                方向=row['借贷标识'], 金额=row['交易金额'],
                对手=opponent, 平台=row.get('平台', ''), 备注=''
            ))
    
    # 2. 按时间排序
    events.sort(key=lambda e: e.时间)
    
    # 3. 滑动窗口检测"通话→资金"模式
    chains = []
    for i in range(len(events)):
        if events[i].事件类型 != '通话':
            continue
        # 查找后续window_hours小时内的资金事件
        for j in range(i + 1, len(events)):
            time_diff = (events[j].时间 - events[i].时间).total_seconds() / 3600
            if time_diff > window_hours:
                break
            if events[j].事件类型 == '资金':
                # 找到"通话→资金"，继续检查是否有后续通话
                chain_events = [events[i], events[j]]
                # 查找资金后window_hours内的通话
                for k in range(j + 1, len(events)):
                    time_diff2 = (events[k].时间 - events[j].时间).total_seconds() / 3600
                    if time_diff2 > window_hours:
                        break
                    if events[k].事件类型 == '通话':
                        chain_events.append(events[k])
                        break
                
                chain_mode = "通话→资金→通话" if len(chain_events) == 3 else "通话→资金"
                chains.append(TimelineChain(
                    本方姓名=person, 对方姓名=opponent,
                    事件序列=chain_events, 链模式=chain_mode,
                    链强度='', 重复次数=0, 时间窗口=window_hours,
                    关键证据描述=''
                ))
    
    # 4. 统计重复次数，评估链强度
    # ... (按对手和模式分组统计)
    
    return chains
```

**多源交叉验证链**：

```python
def build_cross_validation_chain(
    person: str, 
    opponent: str,
    all_bill_data: dict,  # {'银行': df, '微信': df, '支付宝': df}
    call_data: pd.DataFrame
) -> dict:
    """
    构建多源交叉验证链
    逻辑：检查同一对关系在多少个数据源中出现
    出现源越多 → 关系越真实
    """
    sources = []
    for platform, df in all_bill_data.items():
        if df is not None and not df.empty:
            mask = (df['本方姓名'] == person) & (df['对方姓名'] == opponent)
            if mask.any():
                sources.append(platform)
    
    # 话单
    if call_data is not None and not call_data.empty:
        mask = (call_data['本方姓名'] == person) & (call_data['对方姓名'] == opponent)
        if mask.any():
            sources.append('话单')
    
    return {
        '涉及数据源': sources,
        '源数量': len(sources),
        '验证强度': '强(3+源)' if len(sources) >= 3 else '中(2源)' if len(sources) == 2 else '弱(1源)',
    }
```

**验证方法**：
- 检查点1：时序链的时间顺序正确（通话在资金之前）
- 检查点2：时间窗口内的匹配不超时
- 检查点3：3段链的证据强度高于2段链
- 检查点4：交叉验证链的源数量与实际数据一致
