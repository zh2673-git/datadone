# 纪委监委初核报告 —— 数据约束下的三阶解构

> 分析日期：2026-05-04 | 场景：通用知识探索（场景A）
> **核心约束**：仅有银行流水、微信账单、支付宝账单、话单四类数据，无任何外部数据源

---

## 一、是什么（坡度三阶段）

### 阶段1：点出概念

> **一句话定义**：在仅有四类数据的约束下，初核报告的本质是"**自我参照的异常探测器**"——用被核查人自身的行为历史作为参照系，识别偏离、构建关联、形成判断。

**本质特征**（从约束推导）：

| 推导要素 | 逻辑分析 | 结论 |
|---------|---------|------|
| **参照系来源** | 没有外部数据（职务、群体均值等），参照系只能来自哪里？ | **只能来自数据内部**——被核查人自身的历史行为就是唯一的参照系 |
| **异常的定义** | 没有外部基准，"异常"如何定义？ | **相对异常**——偏离自身历史均值/模式的行为就是异常，而非偏离外部标准 |
| **定性的边界** | 没有职务/管辖信息，能定性到什么程度？ | **行为模式定性**——不能说"权钱交易"（需职权证据），但能说"通话→资金→通话时序链存在" |
| **证据的力度** | 纯数据推导的证据能有多强？ | **线索级证据**——足以支撑"建议进一步核查"，不足以支撑"确定违纪违法" |

### 阶段2：建立联系

从"只有四类数据"的约束出发，推导报告能覆盖的维度：

| 属性名 | 类型 | 能否实现 | 推导逻辑 | 深入？ |
|-------|-----|---------|---------|-------|
| **自我基线** | 模块 | ✅ 完全可做 | 从自身历史数据统计均值/分布/趋势 | ✅ 需深入 |
| **异常识别** | 模块 | ✅ 完全可做 | 偏离自我基线即为异常 | ✅ 需深入 |
| **异常量化** | 模块 | ✅ 完全可做 | 偏离倍数、标准差、排名 | ✅ 需深入 |
| **行为模式归类** | 模块 | ⚠️ 部分可做 | 可识别行为模式，但不能确定法律定性 | ✅ 需深入 |
| **因果链** | 模块 | ✅ 完全可做 | 通话+资金的时序排列，交叉验证 | ✅ 需深入 |
| **风险研判** | 模块 | ✅ 完全可做 | 综合以上维度，给出线索级风险判断 | ✅ 需深入 |
| **身份画像** | 属性 | ❌ 不可做 | 没有职务/单位数据 | ❌ |
| **外部基准对比** | 属性 | ❌ 不可做 | 没有群体/行业数据 | ❌ |

### 阶段3：详细解释

**关键转变：从"绝对异常"到"相对异常"**

完整方案中，异常的判定逻辑是：`个人行为 vs 外部基准(职务/群体/行业)` → 绝对异常

数据约束下，异常的判定逻辑变为：`个人行为 vs 自身历史基线` → 相对异常

这两者的区别：
- **绝对异常**：公务员月支出50万 = 异常（因为公务员正常不会这样）
- **相对异常**：某人月支出50万，而其历史月均5万 = 偏离10倍，高度异常

相对异常的局限：无法区分"暴富合法"和"非法所得"。但**这恰恰符合初核的定位**——初核不需要定罪，只需要发现"需要进一步核查的线索"。

**关键洞察：自我基线 + 四源交叉 = 最强组合**

四类数据的真正威力不在于各自独立分析，而在于**交叉验证**：
- 银行数据单独看：某人取现50万 → 只知道取了钱
- 银行+话单交叉：取现50万当天，与X通话3次 → 出现关联线索
- 银行+话单+微信交叉：取现50万后2小时，微信给Y转账48万 → 形成证据链

## 二、为什么（坡度三阶段）

### 阶段1：点出概念

> **一句话总结**：在数据约束下，"自我基线→相对异常→行为模式→交叉因果→线索研判"是唯一可行的逻辑闭环，因为四类数据的内在关联性足以构建内部验证的证据体系。

### 阶段2：建立联系

| 因果 | 因 | 果 | 逻辑 | 类比 |
|-----|---|---|-----|------|
| **有自我基线才能判异** | 没有外部参照 | 必须从自身历史建立基线 | 没有温度计标准时，用昨日温度判断今日是否异常 | 昨日20度，今日35度→异常 |
| **有相对异常才有线索** | 偏离自身基线的行为 | 指向需要关注的时段/对手/金额 | 身体某项指标突然偏离 → 需要检查 | 血压平时120，突然180→需要查 |
| **有行为模式才能归类** | 异常不是随机分布 | 特定异常组合指向特定行为模式 | 症状群→疾病类型 | 发烧+咳嗽+乏力→呼吸道感染 |
| **有交叉才有因果** | 单一数据源的异常可能是巧合 | 多源交叉验证才能构建因果 | 一个目击者可能有误，三个独立目击者一致→可信 | 银行+微信+话单三方验证 |
| **有时序才有方向** | 通话和资金的先后顺序 | 决定因果方向（通话→资金 vs 资金→通话） | 先有因后有果 | 先通话后打款→联络后交易 |
| **有研判才有价值** | 大量异常/模式散落 | 决策者无法快速判断 | 体检报告需要医生解读 | 检验科数据→诊断意见 |

### 阶段3：详细解释

**四类数据的内在关联逻辑**：

```
银行流水：资金多少 + 方向 + 时间 + 对手 + 存取现
微信账单：资金多少 + 方向 + 时间 + 对手
支付宝账单：资金多少 + 方向 + 时间 + 对手
话单记录：通话时间 + 通话对方 + 通话时长 + 对方单位/职务

交叉点 = 对手姓名 + 时间
 ↓
同一对手在多个平台出现 → 关系真实（非偶然）
同一时段有通话+资金 → 因果嫌疑
通话对方有单位/职务 → 身份线索（唯一的外部信息锚点！）
```

**话单中的"对方单位名称"和"对方职务"是四类数据中唯一的外部信息锚点**

这是极其重要的发现：虽然我们没有被核查人的职务信息，但话单中对方的单位/职务可以：
1. 判断交易对手是否为"管理对象"（如果对方单位在被核查人管辖范围内）
2. 判断交易对手是否为"公职人员"（如果对方职务含"局长""处长"等）
3. 交叉验证时的身份标注

## 三、怎么做（坡度三阶段）

### 阶段1：点出概念

> **一句话概述**：在四类数据约束下，报告按"自我画像→基线建立→异常识别→模式归类→时序因果→线索研判"六层递进，每层仅使用四类数据内部可推导的内容。

### 阶段2：建立联系

| 层级 | 核心问题 | 用四类数据能回答什么 | 对应报告章节 |
|-----|---------|-------------------|-------------|
| **第1层：自我画像** | 数据反映的是什么样的人？ | 资金规模/平台偏好/交易对手范围/作息模式/消费特征 | 一、资金画像 |
| **第2层：自我基线** | "正常"是什么样的？ | 月均收支/对手数量/时间分布/存取现比例/金额分布 | 二、行为基线（新增） |
| **第3层：异常识别** | 什么偏离了正常？ | 偏离基线的时段/金额/对手/频率/存取现 + 规避行为 | 三、异常线索（升级） |
| **第4层：模式归类** | 异常组合指向什么？ | 5种可识别的行为模式（数据可推导） | 四、行为模式（新增） |
| **第5层：时序因果** | 能否形成证据链？ | 通话-资金时序链 + 多源交叉链 + 金额对应链 | 五、关联证据（升级） |
| **第6层：线索研判** | 该关注什么？ | 风险等级 + 重点人员 + 调查方向建议 | 六、研判结论（新增） |

### 阶段3：详细解释

#### 第1层：自我画像（基于四类数据的客观描述）

**与完整方案的区别**：完整方案的第1层"人物画像"需要职务、管辖等外部信息。约束下改为"自我画像"——仅用四类数据描述这个人。

| 内容项 | 数据来源 | 计算方式 | 应呈现形式 |
|-------|---------|---------|-----------|
| **资金规模** | 银行+微信+支付宝 | 各平台总进/出+时间跨度 | "银行进X万/出Y万，微信进…，跨度Z个月" |
| **平台偏好** | 银行+微信+支付宝 | 各平台交易占比 | "银行60%，微信30%，支付宝10%" |
| **核心交易对手** | 三类账单 | 按金额TOP10+按频次TOP10 | 表格：姓名/总金额/次数/涉及平台 |
| **作息模式** | 三类账单+话单 | 工作时间vs非工作时间占比 | "工作时间交易占比70%，非工作30%" |
| **现金习惯** | 银行 | 存取现金额/频次/占比 | "存现X次共Y万，取现Z次共W万，占比N%" |
| **通讯模式** | 话单 | 主叫/被叫比、通话时段、TOP联系人 | 表格 |
| **涉及银行** | 银行 | 按交易量排序的银行列表 | "工商银行(60%)、建设银行(30%)…" |
| **账户余额趋势** | 银行 | 最后余额+期间最高/最低余额 | 数值 |

> **当前项目已有此层的约70%**：Word报告的"资金体量"章节已覆盖资金规模、年度TOP3、对手TOP3、存取现、大额转账。需补充：平台偏好、作息模式、余额趋势。

#### 第2层：自我基线（核心新增层）

**这是整个分析逻辑链的基石**——没有基线，后面的异常识别就没有参照。

| 基线指标 | 数据来源 | 计算方式 | 输出 |
|---------|---------|---------|------|
| **月均收入** | 三类账单 | 按月汇总收入→计算均值+标准差 | 月均X万 ± Y万 |
| **月均支出** | 三类账单 | 按月汇总支出→计算均值+标准差 | 月均X万 ± Y万 |
| **月均交易对手数** | 三类账单 | 按月统计唯一对手数→均值 | 月均N人 |
| **月均交易次数** | 三类账单 | 按月统计交易笔数→均值 | 月均N笔 |
| **工作时间交易占比** | 三类账单 | 9-17点交易/总交易 | N% |
| **存取现月均占比** | 银行 | 存取现金额/总金额→按月→均值 | N% |
| **单笔金额分布** | 三类账单 | 均值/中位数/分位数(P25/P75) | 均值X万，中位数Y万 |
| **通话基线** | 话单 | 月均通话次数、时长、对手数 | 月均N次，M分钟 |

**实现方式**：新增 `BaselineAnalyzer` 分析器

```python
class BaselineAnalyzer:
    """行为基线分析器 - 从自身历史数据建立参照系"""
    
    def analyze(self, all_data, call_data) -> dict[str, PersonBaseline]:
        """
        为每个人计算行为基线
        all_data: {'银行': {person: df}, '微信': ..., '支付宝': ...}
        call_data: {person: df} 或 DataFrame
        Returns: {person: PersonBaseline}
        """
```

#### 第3层：异常识别（升级现有逻辑）

**核心升级：所有异常识别必须附加"偏离基线多少"**

| 异常类型 | 当前项目 | 需要升级的内容 |
|---------|---------|--------------|
| **存取现异常** | ✅ 已有识别 | 附加：与个人月均存取现占比的偏离度 |
| **特殊金额** | ✅ 已有识别 | 无需大改，但附加：该对手的特殊金额交易次数占比 |
| **特殊日期** | ✅ 已有识别 | 附加：该日期交易额与日均交易额的偏离倍数 |
| **金额异常(Z-score)** | ✅ 高级分析有 | 附加：具体哪些交易、涉及哪些对手 |
| **高频交易** | ✅ 频率分析有 | 附加：与个人平均交易频率的偏离倍数 |
| **时间异常** | ⚠️ 高级分析有工作时间比 | **新增**：深夜交易(22-6点)清单、非工作时间大额交易 |
| **规避行为** | ❌ 无 | **新增**：4-5万区间密集交易、等额拆分交易 |
| **突增异常** | ❌ 无 | **新增**：某月收支偏离基线超2个标准差的月份 |
| **对手异常** | ❌ 无 | **新增**：突然出现的大额新对手、短暂高频后消失的对手 |

#### 第4层：行为模式归类（核心新增层）

在四类数据约束下，可以识别以下5种行为模式（注意：不能做法律定性，只能描述行为特征）：

| 模式编号 | 模式名称 | 识别规则（纯数据推导） | 需要的数据 | 报告用语 |
|---------|---------|---------------------|-----------|---------|
| **P1** | 周期性收入模式 | 与特定对手存在≥3个月的定期收入（月度标准差<均值的30%） | 账单 | "存在周期性收入特征" |
| **P2** | 资金中转模式 | 大额转入后48小时内取现或转出≥转入金额的60% | 银行 | "存在资金快速中转特征" |
| **P3** | 通讯-资金关联模式 | 通话后24小时内出现与通话对手的资金往来（≥3次） | 账单+话单 | "存在通讯后资金往来关联" |
| **P4** | 规避检测模式 | 4-5万区间密集交易(≥3笔) 或 同对手短期等额拆分(≥2笔) | 账单 | "存在疑似规避大额交易报告特征" |
| **P5** | 特殊关系模式 | 特殊金额(520/1314)+特殊日期+深夜通话的组合出现 | 账单+话单 | "存在特殊关系资金往来" |

**重要说明**：报告用语使用"特征"而非"行为"，因为：
- "存在周期性收入特征" ← 数据可证明
- "存在利益输送" ← 数据不可证明（需职权证据）

**模式匹配评分**：

```python
class PatternRecognizer:
    """行为模式识别器 - 基于四类数据的模式匹配"""
    
    def analyze(self, all_data, call_data, baseline, anomalies) -> dict[str, list[PatternMatch]]:
        """
        对每个人匹配行为模式
        Returns: {person: [PatternMatch(模式名, 匹配度, 关键证据, 涉及对手)]}
        """
        patterns = []
        patterns.extend(self._check_periodic_income(...))    # P1
        patterns.extend(self._check_fund_transfer(...))       # P2
        patterns.extend(self._check_comm_fund_link(...))      # P3
        patterns.extend(self._check_threshold_avoidance(...)) # P4
        patterns.extend(self._check_special_relation(...))    # P5
        return patterns
```

#### 第5层：时序因果链（升级现有逻辑）

| 证据链类型 | 当前项目 | 需要新增/升级 |
|-----------|---------|-------------|
| **间接资金链** | ✅ 大额追踪3层递归 | 保持现状 |
| **存取现话单匹配** | ✅ 当天匹配 | 升级：扩展到±3天窗口 |
| **通讯-资金时序链** | ❌ 无 | **核心新增** |
| **金额对应链** | ❌ 无 | **新增** |
| **规避行为链** | ❌ 无 | **新增**（已在P4模式中识别，此处需形成链） |

#### 第6层：线索研判（核心新增层）

**这是报告最有价值的部分——从数据罗列升级为线索判断**

| 研判项 | 逻辑 | 数据依据 | 输出格式 |
|-------|------|---------|---------|
| **综合风险等级** | 异常数量×严重度×证据强度 | 第3-5层结果汇总 | 高/中/低 + 理由 |
| **重点人员清单** | 交叉关联度最高+异常最集中的对手 | 交叉分析+时序链 | TOP5对手 + 关联特征 |
| **重点时段** | 异常最集中的时间段 | 月度偏离+时序链 | "2024年3月-5月" |
| **行为模式判断** | 匹配到的模式+匹配度 | 第4层结果 | P1(80%)+P3(60%) |
| **证据充分度** | 证据链完整度 | 交叉验证数+时序链数 | 充分/较充分/待补充 |
| **调查方向建议** | 证据薄弱环节指向的方向 | 哪些模式只有部分证据 | "建议核查……的身份及职权关系" |

**风险等级评分逻辑**：

## 七、关键设计决策

### 决策1：基线用什么时间粒度？

**选择**：月度粒度

**理由**：
- 日粒度太细，噪声大（一天可能0交易也可能10笔）
- 季度粒度太粗，可能掩盖月度突增
- 月度粒度与初核关注的"月度收支异常"匹配
- 周度可作为辅助粒度（如"某周交易突然密集"）

### 决策2：偏离基线多少算异常？

**选择**：2个标准差（约95%置信区间）+ 可配置阈值

**理由**：
- 统计学标准：偏离2σ覆盖95%正常范围，超出即为小概率事件
- 但不同场景敏感度不同，通过thresholds.json可配置
- 不用3σ（过于严格，可能漏掉中等程度异常）

### 决策3：模式识别用规则还是机器学习？

**选择**：规则匹配

**理由**：
- 四类数据结构化程度高，规则可解释性强
- 初核报告需要可解释性——"为什么判定这个模式"必须说得清
- 训练数据不足（不可能有标注的违纪违法数据集）
- 规则可配置、可审计、可追溯

### 决策4：报告用语边界

**选择**：严格区分"特征描述"和"法律定性"

| 可以说（数据可证明） | 不可以说（需外部证据） |
|-------------------|---------------------|
| "存在周期性收入特征" | "存在利益输送" |
| "存在通讯后资金往来关联" | "存在权钱交易" |
| "存在疑似规避大额交易报告特征" | "存在洗钱行为" |
| "XX局张三与被核查人有频繁资金往来" | "XX局张三向被核查人行贿" |
| "建议核查张三与被核查人的职权关系" | "张三与被核查人存在权钱交易" |
